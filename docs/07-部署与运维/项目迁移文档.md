## 1. 概述

本文档说明如何将 EAMS 项目从一台 Windows 机器迁移到另一台机器（或备份/换机），**以 Windows 手动（可视化）操作优先**，并保留关键脚本命令供需要时使用。

**核心原则：只复制源码，不复制 `.venv`（Python 虚拟环境）。**

原因：
- `.venv` 是 Python 虚拟环境，体积大（本机约 74MB），内含指向本机解释器的绝对路径（如 `D:\Python\Python314`），复制到新机器后路径失效、不可用
- 虚拟环境可通过在目标机点击几次即可重建，属于「可再生」文件，无需迁移
- 源码才是不可再生的核心资产，迁移它即可 + 目标机重建环境

因此迁移 = **拷贝源码 + 目标机重建虚拟环境**。

## 2. 迁移内容清单

### 2.1 需要拷贝（源码 + 配置文件）

| 文件/目录 | 说明 | 是否必需 |
|-----------|------|---------|
| `main.py` | 程序入口（FastAPI 实例化） | ✅ 必需 |
| `requirements.txt` | 依赖清单（5 个包），目标机安装依赖用 | ✅ 必需 |
| `.env` | 数据库配置（DB_HOST 等） | ✅ 必需 |
| `init.sql` | 建库建表 + 种子数据脚本 | ✅ 必需 |
| `com/` | 全部后端代码（6 业务模块 + common 公共模块） | ✅ 必需 |
| `static/` | 全部前端资源（html / css / js / echarts） | ✅ 必需 |
| `docs/` | 项目文档（本手册所在目录） | 可选（交付/归档建议带） |
| `Dockerfile` | Docker 构建文件（仅目标机用 Docker 部署时） | 可选 |
| `.dockerignore` | Docker 构建忽略清单 | 可选 |

> 拷贝 `com/`、`static/`、`docs/` 时**整体拷目录**即可，内部文件无需逐一处理。

### 2.2 不需要拷贝（可再生 / 无用产物）

| 文件/目录 | 说明 | 处理 |
|-----------|------|------|
| `.venv/` | Python 虚拟环境 | ❌ 不拷贝，目标机重建 |
| `__pycache__/`、`*.pyc` | Python 字节码缓存 | ❌ 不拷贝，运行自动生成 |
| `logs/` | 运行日志（app.log 按天滚动） | ❌ 不拷贝，目标机运行后自动生成 |
| `.idea/` | PyCharm 工程配置（含本机路径） | ❌ 不拷贝，目标机 IDE 可自行重建 |
| `*.log` | 日志文件 | ❌ 不拷贝 |

> 判断标准：**「能否由源码在目标机自动重建？」** 能重建的一律不拷贝（.venv / 缓存 / 日志）；不能重建的才拷贝（源码 / 配置 / SQL）。

## 3. 拷贝源码（Windows 手动操作优先）

### 3.1 首选：资源管理器手动复制 / 压缩

**方法一：压缩包迁移（推荐）**

1. 打开 `D:\workspace-pycharm`（项目 `eams` 所在目录）
2. **右键 `eams` 文件夹 → 发送到 → 压缩(zipped)文件夹**，得到 `eams.zip`
3. 双击进入 `eams.zip`，**删除里面多余的 `.venv`、`logs`、`.idea`、`__pycache__` 文件夹**（右键删除，节省体积、避免误导）
4. 把 `eams.zip` 通过 **U 盘 / 微信 / 网络共享** 拷贝到目标机

> 若嫌手动删麻烦，直接保留完整 zip 也行，但目标机**解压后先删掉 `.venv` 再重建**（见第 4 章）。压缩后不含 .venv 时体积仅数百 KB，传起来最快。

**方法二：整目录复制**

1. 源机选中 `eams` 文件夹 **Ctrl+C**
2. 通过网络共享 / 移动硬盘，在目标机 **Ctrl+V** 粘贴
3. 粘贴完成后，目标机里**手动删除 `.venv`、`logs`、`.idea`、`__pycache__`** 四个文件夹（见 2.2，都不需要）

### 3.2 关键脚本（需要时使用，可跳过）

**打包命令**（Windows 自带 tar，在项目根目录 `D:\workspace-pycharm` 下执行）：

```bash
# 打成 zip，自动排除 .venv 等无需迁移的目录
cd D:\workspace-pycharm
tar -a -c -f eams-src.zip \
  --exclude="eams/.venv" \
  --exclude="eams/__pycache__" \
  --exclude="eams/**/__pycache__" \
  --exclude="eams/logs" \
  --exclude="eams/.idea" \
  eams
```

**robocopy 复制命令**（本机间 / 网络共享，自动排除无关目录）：

```bash
robocopy D:\workspace-pycharm\eams \\目标机共享目录\eams /E /XD .venv __pycache__ .idea logs
```

| 参数 | 说明 |
|------|------|
| `/E` | 复制所有子目录（含空目录） |
| `/XD` | 排除目录：`.venv`、`__pycache__`、`.idea`、`logs` |

## 4. 目标机部署（Windows 手动操作优先）

目标机需预先安装：**Python 3.10+**（本项目开发环境为 3.14，装 3.10 以上均可）、**MySQL 8.0+**。

### 4.1 创建虚拟环境 + 安装依赖

**首选：PyCharm 可视化操作**

1. PyCharm：`File → Open` 打开解压后的 `eams` 项目
2. `File → Settings → Project: eams → Python Interpreter → Add Interpreter → Add Local Interpreter`
3. 选择 **Virtualenv Environment → New**（虚拟环境名默认 `.venv`），Base interpreter 选本机 Python，点 OK
4. 底部 Terminal 执行：`pip install -r requirements.txt`

**命令行替代（不想用 GUI 时）**

```bash
cd eams                                    # 进入解压后的项目根目录
python -m venv .venv                       # 重建虚拟环境
.venv\Scripts\activate                     # Windows 激活虚拟环境
pip install -r requirements.txt            # 安装 5 个依赖包
```

### 4.2 初始化数据库

**首选：Navicat / MySQL Workbench 可视化操作**

1. 新建连接：主机 `127.0.0.1`，端口 `3306`，用户 `root`，填目标机 MySQL 密码
2. 连接后，打开项目根目录 `init.sql` 文件
3. 全选（Ctrl+A）→ 执行 → 自动创建 `school_db` + 7 张表 + 种子数据

**命令行替代**

```bash
mysql -uroot -p < init.sql                 # 创建 school_db + 7 张表 + 种子数据
```

### 4.3 检查配置 `.env`

用**记事本/VS Code**打开项目根 `.env`，确认与目标机 MySQL 一致后保存：

| 配置项 | 默认 | 说明 |
|--------|------|------|
| DB_HOST | 127.0.0.1 | 本机 MySQL 用 127.0.0.1；远程库填对应 IP |
| DB_PORT | 3306 | 端口 |
| DB_USER | root | 用户名 |
| DB_PASSWORD | 150259 | 密码（按目标机 MySQL 修改） |
| DB_NAME | school_db | 库名（init.sql 创建） |

### 4.4 启动服务

**首选：PyCharm 直接运行**

1. 左侧双击打开 `main.py`
2. 右键 → `Run 'main'`（或点击右上角 ▶ 运行）
3. 看到 `Uvicorn running on http://127.0.0.1:8000` 即成功

**命令行替代**

```bash
uvicorn main:app --reload    # 开发模式（热重载）
# 或 python main.py
```

## 5. 验证迁移成功

| 检查项 | 方法 | 期望 |
|--------|------|------|
| 服务启动 | PyCharm 运行窗口观察日志 | `Uvicorn running on http://127.0.0.1:8000`，无报错 |
| 路由完整 | 浏览器 `http://127.0.0.1:8000/docs` | Swagger 页面正常，接口 38 条路径 |
| 接口连通 | 浏览器/命令行 `curl http://127.0.0.1:8000/students/all` | 返回 JSON 数据 |
| 页面可用 | 浏览器 `http://127.0.0.1:8000` | 登录页正常，用 `admin/admin123` 登录成功 |
| 日志生成 | 查看项目根 `logs/` | 启动后自动生成 `app.log`，有业务操作记录 |

> 数据库迁移提示：若需把**存量数据**也迁过去（而非仅空库），用 Navicat「数据传输」或 `mysqldump` 导出/导入，再执行 4.2 初始化。仅迁移空库结构时，执行 `init.sql` 即可。

## 6. 常见问题

| 问题 | 处理 |
|------|------|
| 迁移后启动报 `ModuleNotFoundError` | 依赖没装全：PyCharm Terminal 或命令行 `.venv\Scripts\activate` 后重新 `pip install -r requirements.txt` |
| 启动报连接数据库失败 | 检查目标机 MySQL 已启动、`.env` 的 DB_HOST / DB_PASSWORD 正确 |
| 中文乱码 | 建库时确认字符集 utf8mb4（init.sql 已指定）；MySQL 8 默认 utf8mb4 |
| 目标机没装 MySQL | 先安装 MySQL 8.0+ 并启动服务，再执行 4.2 |
| 只想拷部分源码 | 按第 2 章清单勾选，`com/`、`static/` 两目录不可缺 |
| `.venv` 误拷贝导致启动异常 | 删除目标机 `.venv`，按 4.1 重建即可（虚拟环境本就不该迁移） |
