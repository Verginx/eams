## 2. 模块内部结构

每个业务模块统一为三文件（+ 空 `__init__.py`）：

| 文件 | 职责 |
|------|------|
| `router.py` | 定义 APIRouter 端点、调用 Model（实例）、返回 `success(...)` |
| `vo.py` | Pydantic 请求模型（BaseModel + Field 校验） |
| `model.py` | 数据访问类（实例方法封装 Database） |

## 3. 命名规范

| 对象 | 规范 | 示例 |
|------|------|------|
| 模块目录 | 单数英文 | `student`、`teacher`、`classes` |
| 模型类 | 表名单数 + Model | `StudentModel` |
| VO 类 | 动作/场景 + 名词 | `StudentCreate`、`ClassAssign` |
| 路由函数 | 动词短语 | `list_students`、`add_student` |
| 数据库字段 | snake_case | `class_id`、`head_teacher_id` |

## 4. 分层职责约定

- Router **不做**业务计算：参数已由 VO 校验，只做存在性检查（如资源不存在抛 404）与调用 Model
- Model 专注 SQL：每个实例方法内 `Database()` 于 `try/finally` 中开/关（每次新建连接）
- 跨模块引用单向：`student` 可引用 `classes`/`teacher` 的 Model 做存在性检查；避免反向依赖
- 公共逻辑放 `common/`，不散落业务模块

## 5. SQL 风格

- 一律使用 `%s` 参数占位符（PyMySQL 预处理），**禁止字符串拼接 SQL**
- 级联删除逐条执行（每次新建连接、方法内 commit）
- 查询按需求 `ORDER BY` 稳定排序；分页用 `LIMIT/OFFSET`

## 6. 错误与响应规范

- 成功统一 `return success(data, msg=...)`（来自 `common/response.py`）
- 业务错误 `raise HTTPException(status_code, detail=...)`，由全局异常处理器转 envelope
- 前端校验与后端 VO 校验规则保持一致（必填、范围），前端先行拦截

## 7. 日志规范

- `logs/app.log`：业务操作日志（登录/注册/增删改/选课等），按天滚动保留 7 天
- 关键业务事件（登录成功/失败、注册、增删改、选课等）写入 app.log

## 8. 配置规范（.env）

| 配置项 | 说明 |
|--------|------|
| DB_HOST / DB_PORT / DB_USER / DB_PASSWORD / DB_NAME | 数据库连接 |

缺省值与 `.env` 一致（DB_HOST=127.0.0.1 等）。
